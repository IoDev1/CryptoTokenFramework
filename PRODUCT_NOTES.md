# Product notes — public tool, dynamic data, monetization

Written 2026-09-09. Assessment of the idea: deploy the scorecard publicly, feed it live data
from APIs, earn from ads.

## Verdict

Yes as a tool and portfolio piece. No as an ad business. Build it, but sequence it so the parts
that cost money come last, and do not count on publicity revenue.

## Why ads will not carry it

- Traffic is the constraint. Ad-supported screeners need six-figure monthly pageviews to make a
  few hundred dollars a month. Crypto tool traffic is at cycle lows in a bear market.
- Mainstream ad networks restrict crypto content. Crypto ad networks mostly sell ads for new
  launches and high-emission exchanges: the tokens the framework says to avoid. That undermines
  the premise.
- Data competition: CoinGecko, DeFiLlama, Token Terminal, TokenUnlocks. The edge is the
  opinionated scoring and the user-adjustable weights, not the numbers.

## What can be automated

Split filters by source.

| Source | Filters | Cost |
|---|---|---|
| Mechanical (CoinGecko, DeFiLlama, TokenUnlocks, explorers) | circ %, FDV, drawdown from ATH, revenue/fees, inflation, unlocks, listings | free at low volume |
| Judgment (Claude + web search) | team quality, moat, narrative, catalysts, risks priced in, insider selling context | real money per token per refresh |

Mechanical: refresh daily. Judgment: refresh monthly, cache, store evidence + source URL + date per cell.

## Risks that matter more than revenue

- Liability: a public "12/12, no risks" cell is a problem if wrong. Every cell needs a dated
  source. Plain disclaimer: research output, not advice.
- Regulation: crypto promotion is regulated (EU MiCA, UK financial promotion rules). A ranked
  "high potential" list with ads beside it is closer to the line than a neutral screener.
  Keep framing educational; user-set weights help.
- Unvalidated weights become other people's losses once public. The Nov-2022 backtest in
  FRAMEWORK_v2.md is a prerequisite.

## Plan

1. Finish v2, run the 2022-11-15 backtest. No product until it beats a naive top-20 hold.
2. Static site regenerated by a scheduled job. Pipeline writes one `scores.json`; the existing
   scorecard page reads it. No server, near-zero hosting, survives low traffic.
3. Mechanical filters daily from APIs; judgment filters monthly from Claude with web search,
   evidence stored.
4. Monetize with exchange affiliate links and a newsletter first. Paid tier (alerts, custom
   watchlists) only if an audience exists.
5. Open-source the scoring pipeline. Reputation drives traffic in this niche more than SEO.

## MVP for personal use (started 2026-09-09)

- `scripts/fetch_market.py` pulls CoinGecko market data for the token list and writes
  `data/market.json`. Mechanical filters (FA2 circ %, FC2 drawdown) are computed from it.
- Judgment filters stay as the Opus research output, entered as pass/fail bits.
- The scorecard page embeds both and shows the data date.

## Added 2026-09-10: targets, target market caps, free news agent

- Targets: per-token entry / target / stop / note, edited in the page, kept in the browser and
  exportable to `data/targets.json` (the build injects that file as defaults).
- Target math: price x today's circulating supply (static, ignores emissions) and price x total
  existing supply (fully diluted ceiling), plus "would rank #N" against today's top 100.
- News: `scripts/fetch_news.py` pulls Google News RSS per token (free, no key, last 14 days),
  keeping source, date and link. Opinion step runs on the Claude Code plan, not the API:
  `scripts/news_opinion.py` builds the inputs and calls `claude -p` per batch;
  `scripts/merge_news.py` folds the JSON back. Stance chip + cited headline indices on the page.
- Paid alternative if ever wanted: Anthropic API with claude-opus-5 at $5 / $25 per MTok; a full
  62-token opinion pass is roughly 60-80k input tokens, i.e. well under $1 per run.

Weekly refresh (manual or scheduled):
  python3 scripts/fetch_market.py && python3 scripts/fetch_news.py && python3 scripts/news_opinion.py \
  && python3 scripts/merge_news.py && python3 scripts/build.py

## Brainstorm 2026-09-10: portfolio planner

Ideas raised: portfolio planner framing; follow price and notify; show planned multiple ("x");
L1 revenue per day/month; share your portfolio idea; prove you actually bought; €9.99 forever.

Assessment:
- Planner framing is stronger than "screener": the framework is the why, the plan is the what.
- Notifications: per-user but near-zero compute; a daily job compares price vs each user's
  levels. Telegram bot first (no accounts), email/web push later.
- Planned multiple: already per token; add portfolio-level expected multiple from allocation ×
  target multiple, plus a "only Core holds hit" scenario. Sizing by conviction score is natural.
- Revenue per day/month: DeFiLlama has it; add P/S as valuation context.
- Share: encode the plan in the URL hash, read-only, zero backend.
- Proof of holdings: wallet-signature + on-chain balance check works for self-custody only, not
  exchanges; privacy and "verified bag-holder promotion" risk. Defer; verification, never a
  leaderboard.
- €9.99 forever: viable only because ongoing cost per user is ~0 (model cost is per token, not
  per user). Revenue caps at users × €10; fine for an indie tool. "Forever" means lifetime of
  the product in the terms; use a merchant of record for EU VAT.
- Keep wording as "your plan", never "our recommendation": planner + alerts sits closer to
  advice than a screener does.
